③ How it works step 2 / 3

Branches = parallel timelines

git branch → git checkout → git merge

Try risky changes on a copy. Works? Merge it back. Doesn't? Delete it. Main stays safe either way.

③ How it works step 3 / 3

5 commands you'll use every day

$ git init
📁  starts tracking this folder
$ git add .
📋  stages your changes
$ git commit -m "first save"
📸  saves a permanent snapshot
$ git branch feature
🌿  opens a new timeline
$ git merge feature
🔀  combines it back into main
Watch out

3 mistakes every beginner makes

✕One giant commitCan't undo just one change without undoing everything
✕Skipping .gitignoreJunk files — or worse, passwords — get uploaded
✕"fixed stuff" as a commit messageFuture-you won't have a clue what changed
Do this instead

3 habits that make you look like a pro

✓Small, frequent commitsEasy to review, easy to undo
✓Messages a stranger could understand"Fix login redirect bug" beats "update"
✓One branch per featureKeeps the main timeline always working
